# AI + BI 评估报告

> 评估日期：2026-08-07

## 一、概念定义

**AI + BI**（人工智能 + 商业智能）是指将 AI 能力（尤其是大语言模型 LLM、机器学习）深度融入 BI 分析全流程的新一代分析范式，实现从"人找数据"到"数据找人"、从"专业分析师工具"到"全员对话式分析"的转变。

核心演进路径：
- **传统 BI**：报表 + 拖拽式自助分析（依赖专业人员）
- **增强分析（Augmented Analytics）**：自动洞察、异常检测、NLQ 自然语言查询
- **AI 原生 BI（Agentic BI）**：LLM 驱动的对话式分析、多轮推理、自主分析 Agent

## 四、关键技术架构

```
用户自然语言提问
      ↓
[LLM 意图理解] → [语义层/指标平台]（关键！统一口径）
      ↓
[Text-to-SQL / 语义查询生成]
      ↓
[数据引擎执行] → [结果校验 & 可视化渲染]
      ↓
[LLM 生成解读 & 建议]
```

**架构要点：**
1. **语义层是成败关键**：没有统一指标口径，AI 问数准确率无法保障
2. **RAG + 领域知识**：注入业务术语、表结构、历史查询提升准确率
3. **Text-to-SQL 准确率**：复杂查询场景下仍是瓶颈（一般 70-90%）
4. **Agent 架构**：规划-执行-反思的多轮分析能力是下一竞争焦点

## 五、价值与收益

- ✅ **降低分析门槛**：业务人员自助取数，IT/数据团队从取数需求中解放
- ✅ **提升决策效率**：从"提需求→等报表"（天级）到"即时问答"（秒级）
- ✅ **发现隐性洞察**：自动异常检测与归因，主动推送
- ✅ **知识沉淀**：分析思路、指标口径沉淀为可复用资产

## 六、挑战与风险

| 风险 | 说明 | 应对建议 |
|------|------|----------|
| **幻觉与准确性** | LLM 可能生成错误 SQL 或错误解读 | 语义层约束 + 结果可解释 + 人工校验机制 |
| **数据治理要求高** | 垃圾进垃圾出，口径混乱会被放大 | 先建指标体系/语义层，再上 AI 问数 |
| **数据安全与权限** | 自然语言绕过传统权限管控的风险 | 行列级权限继承 + 查询审计 |
| **成本** | LLM 调用成本、License 溢价 | 评估调用量，考虑私有化/小模型方案 |
| **组织 adoption** | 业务习惯转变慢 | 从高频场景试点，树立标杆用例 |

## 八、趋势展望（2026+）

1. **Agentic BI 成为主战场**：从"一问一答"走向"自主完成多步分析任务"
2. **语义层/指标平台成为标配**：AI 问数准确率的竞争本质是语义层竞争
3. **数仓 + BI + AI 融合**：Snowflake/Databricks/Fabric 推动"数据 AI 一体化"
4. **嵌入式与主动式分析**：AI 洞察推送到 IM/邮件/业务系统，BI 无处不在
5. **结论**：AI+BI 方向明确、价值真实，但**落地前提是数据治理与语义层建设**，建议"小步试点 → 验证准确率 → 规模推广"。
