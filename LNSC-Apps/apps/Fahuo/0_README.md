# LNSC 全链发货平台 | LNSC Full-Chain Delivery System

国内发货全链路内网应用，覆盖录单、承运商下单与面单、清单、SAP 视图和标签管理。前端为原生 HTML/CSS/JavaScript，无框架、无构建；生产后端为 Python 标准库，数据使用 SQLite。

> **本文只描述当前有效规则和架构。** 修改前必读 [CONTRIBUTING.md](CONTRIBUTING.md)。
> 变更过程见 [CHANGELOG.md](CHANGELOG.md)，事故复盘见 [docs/carrier-incidents.md](docs/carrier-incidents.md)。
> `docs/archive/` 是只读快照，不是需求来源；禁止依据其中的旧“终定”恢复已撤回方案。

## 当前状态与架构

五个模式均可用：**录单、下单、清单、SAP、标签**。追溯/可视化页已移除。API 不可达时前端可降级为本地临时模式，但刷新会丢失暂存数据；生产承运商未配置凭证时必须报错，不得伪造正式运单。

```text
HMI 触屏 / PC 浏览器
  └─ pages/*.html + assets/{css,js,images,fonts,vendor}
       │ fetch JSON（同源 /apps/fahuo/api/，本地可直连 :8091/api）
       ▼
server.py（生产，Python 标准库，:8091）

  ├─ /opt/label/data/label.db（标签平台生产库）
  ├─ carriers/（顺丰、德邦、跨越协议）
  ├─ Upload/（订单附件）
  └─ ShippingPhotos/ + shipphotos.json（共享盘照片及索引）

server.js（仅本地开发）
  └─ 子进程调用同一个 carriers/cli.py，不维护另一套协议实现
```

### 模块边界

- `pages/`：HTML 页面结构和展示，不实现承运商签名或协议。
- `assets/js/pages/`：与页面对应的交互脚本；`assets/css/`、`assets/js/`：跨页布局、主题、顶栏和统计。
- `assets/images/`、`assets/fonts/`、`assets/vendor/`：图片与图标、字体、第三方浏览器库。
- `server.py`：唯一生产 API 服务，负责 SQLite、静态文件、附件、路由刷新、标签 API 和承运商分发。
- `carriers/`：一家一文件；公共 HTTP/签名/PDF 逻辑放 `base.py`，注册分发在 `__init__.py`。
- `label/`：已并入的标签前端和资源；不启动独立服务。`pages/6-label.html` 用 iframe 隔离其 CSS/JS。
- `ot_label.py`：专车/自提厂内面单 PDF 渲染及缓存，不是顺丰反向回签单的替代方案。

### REST API

| 方法 | 路径 | 当前用途 |
|---|---|---|

| POST | `/api/orders` | 新建订单 |
| POST | `/api/orders/manual-waybills` | 批量新增独立的系统外运单记录；单事务、最多 100 条，拒绝订单 ID，不关联或修改已录订单，不调用承运商下单 |

| DELETE | `/api/orders/<id>` | 删除订单 |
| GET | `/api/stats` | 昨日发货、今日待发货、计划发货、今日回单 |
| GET / POST | `/api/addrpool` | 查询共享地址池 / 按地址键去重新增 |
| GET | `/api/upload?dn=` | 查询某目录附件；不带 `dn` 返回全量附件计数 |

| DELETE | `/api/upload?dn=&name=` | 删除附件，空目录自动移除 |
| POST | `/api/carrier/order` | 快递下单或生成专车/自提厂内单号 |

| POST / GET | `/api/carrier/label_ot` | 渲染 / 获取专车、自提厂内 PDF 面单 |
| GET | `/api/label/health` | 标签平台健康检查和模板、客户、历史计数 |
| GET / PUT | `/api/label/db` | 标签整库读取 / 事务清写；缺省分表不变，每天首写自动备份 |

## 承运商集成

### 共同架构与编号铁律

- 统一入口为 `/api/carrier/order|route|label|cancel`，不开独立承运商服务。
- 密钥由本地 `carriers.env`（权限 600）或 systemd `EnvironmentFile` 注入，**只记录变量名，不记录或提交真值**。
- 未配置生产凭证直接报错；正式模式不得生成模拟快递单号。
- **DN 只是平台内部标识**，用于列表、队列、附件目录和厂内 ZC/ZT 单号，永不下发承运商。
- 顺丰 `orderId`、德邦 `custOrderNo` 只能由服务端 `next_oid()` 分配；`oid.seq` 持久自增，清库、取消、删单、重建和部署均不复用。
- 每环境的 `oid.seq` 独立保存；运维跳号时必须评估各环境，不得用本地序列覆盖生产序列。
- 下单返回的 `order_id`、德邦 `logistic_id` 存入 `order_resp`，取消时使用；老单缺这些字段时需要人工处理。
- 官方面单上的“订单号”显示承运商客户单号而非 DN，这是两套编号体系的正常表现。

### 取消与路由共同规则

- 仅 `route_status=待揽收` 的承运商订单允许取消；专车/自提只清本地厂内单号。
- 承运商侧已取消而本地仍待取消时，目标状态一致，可同步回待下单。
- 取消成功后清空运单字段，允许修改数据后重新下单，但**新承运商客户单号仍不得复用**。
- 顺丰 A1004 先排除密钥 CRLF/空白污染，再判断服务权限；下单、路由和云打印权限分别开通。
- 德邦下单异步入账，取消保留 5 秒、15 秒退避重试；轨迹使用 `mailNo + customerCode`。
- 空路由不能一律解释为“待揽收”，必须保留承运商错误或无路由原因。

### 顺丰：下单与产品

- 下单接口：`EXP_RECE_CREATE_ORDER`；表单签名，运单从 `apiResultData.msgData.waybillNoInfoList` 读取。
- 产品映射固定：**`expressTypeId=1` = 特快，`2` = 标快**。近线无特快时可能降级，不得据降级结果推翻映射。
- `routeLabelInfo.expressTypeCode` 不用于判断实际产品；`proCode` / `limitTypeCode` 才表示实际执行产品。
- 托寄物原样传递，不自动填充、不追加“的回单”或其他回单后缀；为空时可能显示丰桥模板/账户默认文案。
- 付款方式：月结 `1` 且带月结卡、现结 `1`、到付 `2`；保价使用 `declaredValue`，未填则不保价。
- 顺丰配置变量：`SF_APP_KEY`、`SF_APP_SECRET`、`SF_CUST_CODE`。

### 顺丰：纸质回单、拍照回传与回签单

**请求参数不得混用：**

- 纸质回单：`isSignBack=1`。IN03 是纸质签单返还的增值服务费目，下单无需再向 `serviceList` 下发 IN03。
- 拍照回传：`serviceList:[{"name":"IN91","value":"13"}]`；IN91 是拍照回传，`13` 是签回单拍照。
- 纸质签单与拍照回传组合时按上述两条分别传递；禁止使用 `isSignBack=2/3` 代替 IN91，也不使用 `attrCode POD`。
- 当前选择同时勾选纸质和拍照时，回单勾选时序和实际请求仍需人工验证；官方完整服务表见 [增值服务产品表](carriers/增值服务产品表-20260924164208.pdf)。
- 仅拍照回传在主单备注追加“需拍照回传”；纸质回单不追加“需纸质回单”，且两者都不得改变托寄物原文。

**响应与存档：**

- `waybillType=1/2` 才是主/子件；`waybillType=3` 是签单返还回单运单，不计件数、不参与主/子件合并打印。
- 回单运单存入 `order_resp.sign_back_no`，实际备注和服务存档在 `order_resp.remark`、`order_resp.serviceList`。
- 回单路由另存 `sign_back_status`、`sign_back_date`、`sign_back_final`，不得与主运单状态混用。
- 回单追踪窗口 `SIGN_BACK_WINDOW_D=30`；主单签收后查回单运单，复用 `route_checked_at` 节流。

**实物回单与展示：**

- `created_at >= SIGN_BACK_MANUAL_SINCE`（当前为 `2026-09-29`）的新单，回单运单终态只提示并停查，**不自动置 `returned`**；人工核实实物后才可手动置回单。旧单保持历史逻辑，不回溯。
- 清单回单日期优先取人工 `returned_at`，否则取回单运单 `sign_back_date`；**不得取主单 `signed_at`**。
- 回单已签收显示可点击日期徽章，未签收且有路由显示 `回单 > <sign_back_status>`；点击仅打开回单运单路由，不回写主单状态。点击查询须显式带原订单收件 `phone`（空则寄件 `emp_phone`）的后四位，因为 `SF106` 回单号不能在后端按主运单字段反查电话；否则顺丰到付回单会误报 20028“月结卡号不匹配”。
- 无回单运单时，人工回单记录可回退显示主单路由并明确提示。
- 回单到方地址由顺丰账号侧维护，平台没有也不新增地址配置 API。

**回签单打印：**

- 调用云打印 `COM_RECE_CLOUD_PRINT_WAYBILLS`，当前标准模板为 `fm_76130_standard_LKLPZA6VYES4`，76×130mm。
- 云打印返回 URL + token，下载请求必须带 `X-Auth-Token`；新单同步延迟由前端按 1/2/4/8 秒退避。
- 打印回签单联时，SF106 回单号只能进入 `documents[].backWaybillNo`，且 `masterWaybillNo`、`branchWaybillNo` 为空。
- 默认打印主面单；传 `back_no` 才追加回签单联。回签单获取失败不阻塞主面单，同一订单重复打印不得重复下单。
- `optional_no + with_optional=1` 仅保留旧调用兼容；新功能使用 `back_no`。
- `ot_label.py` 只负责专车/自提厂内面单，不得作为顺丰回签单通道。

### 顺丰：主运单路由

- 接口 `EXP_RECE_SEARCH_ROUTES`，`trackingType=1`，运单数组为 `trackingNumber`。
- 所有请求必须带长参数 **`checkPhoneNo`**，值为收方或寄方手机号后四位；短名 `checkNo` 无效。
- 平台优先取收件 `phone`，员工寄件 `emp_phone` 兜底，去非数字后取后四位；DB 无记录时可用 API `phone4=` 手工覆盖。
- 响应对应 `apiResultData.msgData.routeResps[0].routes[]`；空路由显示 `reasonRemark`（包括 20028），不得盲显“待揽收”。
- 状态以 `firstStatusName` 为主要来源，最新节点文本存 `route_latest`。
- 自动刷新有两条通道：加载 `/api/orders` 触发，以及常驻 `_route_timer`；白天 07:00–22:00 每 26 分钟一轮，夜间不刷。
- 每单节流 `ROUTE_THROTTLE_S=300` 秒；签收/回单/已送达/已提停刷，失败保留旧值。常量由 `ROUTE_DAY_INTERVAL_S`、`ROUTE_DAY_START`、`ROUTE_DAY_END` 等配置。
- 首次进入签收、回单、已送达、已提类状态时维护 `signed_at`，供清单和导出使用。

### 德邦

- 下单和签名沿用 `standard-order` / dpapi 协议；`companyCode` 同时在顶层和 params 中，`digest` 按 params 原文、appkey、毫秒时间戳计算。
- `logisticID` 每单消耗一个，由 `.db_logistic_seq` 持久保存；固定环境可按配置停用递增，但不得复用。
- `payType`：**0=寄付现结，1=到付，2=寄付月结**；大客户模式可能不支持 0。
- 面单使用官方 `queryBillPrint`；`customerCode` 必须是客户编码，不能填公司编码。
- 返回 OBS 预签名 URL，不需要 token；PDF 为预生成的 76×130mm 一联单，接口不支持选择尺寸，浏览器打印时可等比适配 100×150mm 标签纸。
- 面单异步生成，可能延迟数分钟；前端按 5/10/20 秒退避，仍在生成时提示稍后重打，**不回退非官方 HTML 面单**。
- 轨迹响应读取 `responseParam.trace_list`，无记录是空数组；节点归一化为平台统一格式。
- 德邦纸质回单使用 `addServices` 子字段 `{backSignBill:"1", returnRequirement:"R1", returnBillQty:1}`；三项必须位于 `addServices` 内，放顶层会被忽略。
- 德邦没有顺丰式 type=3 回单运单追踪；拍照回传在非顺丰页面禁用，不能对德邦调用 IN91，相关人工流程只保留本地记录。
- 环境变量：`DB_APP_KEY`（公司编码）、`DB_APP_SECRET`（签名 appkey）、`DB_CUST_CODE`（客户编码）、`DB_LOGISTIC_ID`；可选 `DB_CANCEL_IF`、`DB_LOGISTIC_INCR`。

### 跨越、专车与自提

- `kye.py` 仍是待正式报文的骨架，未接入前不得描述为生产可用。
- 专车/自提生成厂内 `ZC/ZT + 日期 + 流水` 单号，流水由 `ot_seq` 持久维护，取消和删单不复用。
- 厂内面单由 `ot_label.py` 生成缓存 PDF，与快递官方面单路径分开。
- 专车（专车直送）点“> 送达？”填写关闭备注并置“已送达”；自提（待自提）点“> 已提？”填写关闭备注并置“已提”。备注存 `close_note`；已送达、已提或已关闭的专车/自提不能再次下单。

## 部署、备份与安全

### 安装与服务

1. 首次或配置变化时运行 `sudo bash 1_install-api.sh`；按提示填写服务器地址，确认 systemd、`carriers.env`、备份任务和照片索引任务。
2. 生产服务是 `fahuo-api`，生产环境不要启动 `server.js` 或独立 `label.service`。
3. 纯静态 HTML/CSS/JS 改动通常不需要重启；`server.py` 改动必须 `systemctl restart fahuo-api`。
4. 日常部署统一从 `LNSC-Apps` 根目录运行 `powershell apps/SSH/deploy.ps1 fahuo`；纯前端改动加 `-NoRestart`，不得用手工 `scp` 单文件覆盖替代标准流程。
5. 部署后检查服务、目标页面、`/api/stats` 和本次涉及的关键静态资源/API。外层强制刷新不保证 iframe 内资源已刷新。

### 文件同步边界

- 只同步运行必需的页面、共享资源、标签前端、正式承运商模块、生产服务和部署脚本。
- **永不同步或覆盖**：`fahuo.db*`、`oid.seq`、`carriers.env`、`Upload/`、`ShippingPhotos/`、`shipphotos.json`、`label/data/`、`carriers/.db_logistic_seq`。
- 探针、测试、临时回填脚本、`__pycache__/`、`label/server.js`、`label/import-customers.js` 不进 webroot。
- 不递归清空或强制删除整个应用目录；`ShippingPhotos/` 可能仍挂载，不能改成普通空目录。
- 修改缓存版本号时同步检查外层 iframe、`label/index.html` 和设计器 CSS 引用；版本号不能代替功能验证。

### 数据库备份

```bash
# 停止服务，复制数据库，再启动
sudo systemctl stop fahuo-api
sudo cp /var/www/lnsc-apps/apps/fahuo/fahuo.db \
  /root/fahuo.db.bak.$(date +%Y%m%d_%H%M%S)
sudo systemctl start fahuo-api

# 日常校验
sqlite3 /var/www/lnsc-apps/apps/fahuo/fahuo.db 'PRAGMA integrity_check;'
```

生产通过 `6_backup_db.sh` 和 cron 每日在线备份，使用 `YYYY-MM-DD_HHMMSS` 命名，保留 30 天。停止服务是进行手工整目录迁移时的保守方案，不能用不完整的停止操作替代正常在线备份。标签库由 `/api/label/db` 每天首写自动备份，保留 7 份。

### 发货照片挂载与索引

- `4_mount_shipphotos.sh` 将发货照片共享盘挂载到应用内 `ShippingPhotos/`；fstab 负责开机挂载。
- `5_scan_shipphotos.sh` 扫描 DN 命名图片并生成 `shipphotos.json`，root cron 每 5 分钟重扫。
- 前端读取静态 `shipphotos.json` 并添加时间戳防缓存，图片路径为 `ShippingPhotos/<相对路径>`。
- 挂载目录和索引属于运行时资料，部署不得覆盖。

### 安全边界

- `7_harden_webroot.sh` 对敏感扩展和 `carriers.env` 返回 404，修改后需 reload nginx 并验证正常页面未受影响。
- 至少保护 `.py/.pyc/.env/.db/.db-shm/.db-wal/.log/.sh/.seq`；`.csv` 是否加入仍待结合实际下载需求确认。
- 仓库不得包含数据库、上传、密钥和日志；历史提交中曾出现的旧承运商密钥必须确认已轮换，不能以当前文件已删除视为轮换完成。
- 页面中的下单/异常软密码只是操作防误触，不是安全认证边界，不得据此开放管理接口。

## 录单模式（pages/1-entry）

### 三类订单与字段

- **发货单**：SO、DN、省市区、街道、姓名、电话、要求发货日期、优先级、备注、SO 负责人。DN 支持 `, / | 空格 换行` 分隔，一单多 DN 原样保存。
- SO 不限制发货日期，不做未来日期校验，也不限制 16 位 SAP 格式。
- **外协单**：表单号码标签统一为 DN，值使用 PO；包含采购员、公司电话、省市区、街道、姓名、电话、公司、日期、优先级、备注。
- **其他**：员工姓名/电话、姓名/电话、省市区、街道、日期、优先级、备注。
- 三类按各自视图校验；发件方结构化信息随订单保存，备注展示通过 `cleanNote` 剥离结构化标签，搜索仍覆盖完整内容。
- SO 与 SO 负责人同一行；占位文字为“请选择SO负责人”，存储字段仍为 `is_owner`。历史值不在固定选项时，编辑回填应临时保留原值。

### 异常单

- 勾选异常需要软密码弹窗；取消或关闭弹窗不能改变原状态。
- 异常后可选择“可以发货”/“暂不发货”，未勾选异常时子选项禁用；两个发货子选项使用圆形勾选框，禁用态保留清晰灰色轮廓，“异常”和“显示异常行”保持方形。
- 异常设置、发货子选项和“显示异常行”筛选位于同一工具条并始终保持单行；异常设置与子选项共用一个背景块，“显示异常行”使用带独立边框、背景和间距的单独背景块。录单类型栏固定为 388px，粘贴与解析面板分配剩余空间。禁用态使用弱化文字，所有标签与复选框垂直居中对齐。
- 异常 DN 使用 `年月日>序号>?` 形式，异常行以黄色区分；`abnormal` 与 `is_owner` 均须进入插入、更新和 JSON 返回路径。
- 列表支持“显示异常行”过滤；类型按钮组只包含“发货单 / 外协单 / 其他”，用于切换录单类型，不提供“自提”清单筛选。异常长号码也必须服从表格宽度和省略规则。

### 地址、编辑与附件

- 智能地址解析支持省市区、街道、姓名、电话和英文姓名；“识别并覆盖”前必须确认。
- 地址池搜索覆盖省市区、公司、街道、姓名、电话、`company` 和完整 `addr_key`；常用地址默认可保存，按地址键去重，上限 5000 条。
- 点行回填后可 PUT 保存；已有运单号的订单禁止行内编辑。复制新增可基于现有行创建新单。
- 发货单附件目录键为首个 DN，外协单为 PO；支持多文件上传、预览、下载和删除。录单页多附件始终只显示一个完整文件名，整行淡入淡出轮换，不出现上下半行或两个删除按钮。
- 录单/下单备注最多显示 3 行并保留悬浮全文；清单备注规则见清单章节。

## 下单模式（pages/2-order）

### 队列、筛选与状态

- 左侧队列只显示待下单订单，下单成功后移出，防止重复下单；按发货单、外协单、其他过滤。
- 打单列表以最近 7 天待下单订单和全部已下单订单为基础，再按完成状态过滤，支持按类型切换视图。专车未手动置“已送达”时一直保留，不按录单或发货日期自动移除；手动送达当天仍显示，从 `signed_at` 完成日的下一自然日起只从下单列表隐藏，订单记录及清单页显示不变。无完成时间的存量已送达专车按历史完成记录隐藏，避免永久滞留。
- 外协单队列和列表使用 PO 值及 `98260` 前缀上标，但列标题统一为 DN。
- 运单悬浮提示显示承运商实际产品；路由文本来自真实 API，`_mock-timeline.html` 只是本地静态浏览器组件。
- 选中行中任一为已揽收或之后状态，或专车/自提已送达、已提、已关闭时，下单按钮禁用并明确置灰。
- 下单操作有软密码防误触、二次确认和防连点；扫码枪按当前页面输入流程使用。

### 面单与打印

- 四套 HTML 备用模板：标准 80×130、黑边 70×125、顺丰红棕 80×130、德邦蓝黑 70×125。
- 生产快递优先使用承运商官方 PDF；顺丰多件合并，德邦等待官方异步面单，专车/自提走厂内 PDF。
- 专车/自提厂内面单保留 CODE128 条码，不显示或生成二维码；收件信息使用通栏，长地址和目的地公司不再受二维码栏挤压。
- 官方 PDF 按其实际尺寸处理，HTML 备用模板按当前打印样式等比适配；不要为了统一尺寸改写官方 PDF 内容。
- 外协单面单号码位显示 PO，与发货单 DN 的字号一致；运单备注不重复堆砌 PO。
- 同一订单的打印、预览和重打不得触发再次下单。

### 打单列表与附件

- 承运商、运单号和下单状态按当前合并列展示，备注使用纯备注；SO 和备注悬浮可查看完整内容。
- DN 第二行 badge 组包含要求发货日期、承运商下单日期和负责人/采购员/发件人。
- `printed_at` 是实际承运商下单时间，导出和 badge 不得改用主单签收时间。
- “查看”列展示已上传附件；文件较多时按页横向滚动，初始显示较新的文件。
- 发货单按 DN、外协单按 PO 查询附件；Excel/CSV 使用相对路径下载，不尝试伪造在线预览。
- 多选取消只处理已下单且未揽收的行，逐单报告失败，其他行继续；未下单行不得当作承运商取消成功。

## 清单模式（pages/3-list）

### 数据、筛选与导出

- “发货单”前的“＋”打开系统外运单手工补录弹窗；点击“添加外部运单”建立空白明细，逐条填写 DN、SO、公司、地址、姓名、电话、备注、承运商、运单号和路由状态，可连续添加多条，每条明细以带序号的独立卡片分隔。默认承运商和每条明细均提供可直接展开的下拉框，列出 29 个国内常见快递、快运和零担品牌；选择“其他（手动输入）”可填写其他名称；这里不搜索或展示系统内订单候选，因为补录对象按定义尚未进入系统。
- 批量保存调用 `/api/orders/manual-waybills`，每条都生成独立的“发货单”记录，绝不按 DN、SO 或订单 ID 关联、覆盖已录订单；接口明确拒绝携带 `id` 的请求。默认路由状态仅提供“已签收”，新增明细据此默认带入，逐条明细的状态候选不含“已送达”；默认承运商/状态可应用到全部明细，每批最多 100 条，在同一 SQLite 事务中整批成功或失败，不调用承运商下单接口。新记录写入 `printed_at`，签收/送达状态写入 `signed_at`，`order_resp.manual_entry` 记录补录来源。
- “发货单 / 外协单 / 其他 / 自提”四个筛选按钮统一单选互斥，任意时刻最多一个高亮，再点当前项可取消并恢复全部；前三个按单据类型筛选，“自提”仅显示 `carrier === "自提"` 的记录，不新增单据类型。选中的按钮筛选再与关键词和右侧看板 `?f=` 基础集合共同生效，计数、复制和导出使用最终可见集合，不提供独立优先级筛选组。“＋”是新增操作，不参与筛选选中。
- 顶部工具栏按类型、搜索、单数、分享操作分区；筛选按钮和搜索框统一 40px 高，单数与等宽图标按钮垂直居中，窄搜索区允许收缩但不改变清单表格列宽。
- 搜索覆盖号码、地址、收件人、电话、备注、运单，以及 DN 第二行的 `is_owner`、`buyer` 等负责人字段。
- 点击“发货单 / 外协单 / 其他 / 自提”任一项时，当前基础集合中去重后的姓名直接以主题色标签在搜索框内单行横排显示：只罗列我方人员，不使用对方联系人/接收方 `name`：“发货单”取 SO 负责人 `is_owner`，“外协单”取采购员 `buyer` 并兼容旧备注标签，“其他”取员工 `emp_name` 并兼容旧备注发件人；“自提”按每条记录的实际单据类型取上述对应我方人员；四个类型筛选按钮使用 8px 水平内边距和 4px 间距的紧凑布局；有候选时姓名区与搜索输入区严格按 2/3 和 1/3 分配；姓名区仅显示能完整容纳的姓名，不裁切半个标签；不显示左右箭头，仅在最右保留一个加大的深色向下箭头，点击后在搜索框下方展开全部姓名并自动换行，可从完整列表直接选择姓名，点击姓名、再次点击向下箭头、搜索框外部或按 Esc 收起；窗口及字体尺寸变化后自动重排。点击标签立即按现有关键词口径筛选，未选标签为浅色底深色字，选中标签为高对比深色底白字并显示 `×`，再次点击可取消；选中姓名后可继续输入关键词，两个条件以 AND 叠加筛选，且点选姓名不会清空已输入内容；切换或取消类型筛选会清除已选标签，但保留手工输入的搜索内容。未选择筛选类型时不显示姓名标签，输入区恢复全宽。
- 导出、复制、邮件和 Teams 共用当前字段口径，包含下单时间 `printed_at` 和主单签收时间 `signed_at`。
- 回单日期导出和展示必须与主单签收时间分开，取人工回单日或回单运单签收日。
- 顶部警告图标表示存在未下单紧急单；样式为与其他图标同尺寸的红色背景、白色居中图标。
- `assets/js/stats.js` 是五页唯一共享统计实现，不得在各页复制独立统计逻辑。

### 附件与发货照片

- 发货照片与上传文件图标在同一行；照片来自共享盘索引，附件计数通过一次全量 `/api/upload` 请求取得。
- 点击附件图标打开加宽预览弹窗，桌面最大宽 960px，小屏按 94vw 自适应；发货照片弹窗仍保持原宽。图片直显、PDF 内嵌、Excel 用 SheetJS、Word 用 docx-preview，Excel/Word 支持滚轮缩放及按住鼠标左键拖动平移。清单页须先加载本地 `jszip.min.js` 再加载 `docx-preview.min.js`，与下单页一致。
- 弹窗头部“+ 上传”写入当前 DN/PO 对应目录，完成后刷新计数、图标和文件列表；文件名可作为下载链接。
- 共享盘照片图标有匹配图片时可点击预览，无照片时保持占位，不把上传附件与共享盘照片混为同一数据源。

### 回单、路由与专车

- 下单状态列同时容纳已下单/待下单和回单徽章，**没有独立回单日期列**。
- 回单日期或在途状态徽章按“顺丰：实物回单与展示”规则渲染；只有当前可点击的回单徽章打开回单路由。
- 主运单号点击打开主运单步骤弹窗；查回单路由不得回写主单 `route_status`。
- 专车“> 送达？”和自提“> 已提？”分别在“专车直送”/“待自提”路由状态下方单独一行；弹窗填写关闭备注后分别置“已送达”/“已提”，保存 `close_note`。
- 页面提供手动刷新路由时，应调用 `/api/carrier/refresh_route?waybill_no=`，并保留服务端电话后四位和错误原因处理。

## 表格与页面版式硬规则

1. **列数一致性**：订单表的表头、`colgroup` 和每个数据行必须一致；每行包含 `colspan` 展开后的格子数也必须等于列数。
2. **禁止用 `colspan` 做视觉跨列**：需要让 DN badge 或姓名越出本列时使用 `overflow: visible`、限宽、层叠和省略规则，不增加或删除格子。
3. **DN 两行**：第一行是号码，外层 `.dn-num` 限宽；第二行是负责人或日期 badge 组。发货单 DN 使用 `82600` 前缀上标，外协单 PO 使用 `98260` 前缀上标，其他类型无号码时保留占位。
4. 下单/清单第二行 badge 组为要求发货日期、承运商下单日期、姓名；录单第二行保持单姓名 badge。黑底白字、加粗、微圆角，允许按当前 CSS 视觉溢出，但不得盖住不可牺牲的相邻信息。
5. 调整 `.dn-badges`、`.dn-owner`、`.nm-span` 或 `:has(...)` 时，必须同时验证录单、下单、清单及外协窄 DN 视图；长号码本身仍应省略，不能随 badge 一起溢出。
6. 录单地址街道阈值 18 字、清单 13 字：不超过阈值时省市区和街道第一行、公司第二行；超过时街道第二行、公司第三行。无公司则不渲染公司行。
7. 录单/下单备注最多 3 行，清单备注单行省略并提供悬浮全文及横向查看；所有备注悬浮内容均不受视觉截断影响。三类列表的备注单元格尾部均提供复制图标，复制当前单元格的完整纯备注且不触发行操作；空备注禁用按钮，备注列宽保持不变。
8. 主内容区按 1080P 目标一屏使用；表格不出横向滚动，弹窗不超过 85vh。共享尺寸变化必须检查五页页壳。
9. HELP 页复用同一页壳、五页导航、五张统计卡和顶栏，内容每行 3 个步骤；不恢复已移除的大幅示意图。

## 标签模式（pages/6-label + label/）

### 当前集成方式

- 标签是左侧导航第五个模式，右上标签图标已移除；`6-label.html` 使用与其他页面一致的页壳和 iframe。
- iframe 加载 `label/index.html`，隔离标签自身全局 CSS/JS；标签 API 由 `fahuo-api :8091` 提供，原 Node :8092 和独立服务已退役。
- 标签生产库仍为 `/opt/label/data/label.db`；整库事务写入，缺省分表不变，每天首写备份并保留 7 份。
- 页面没有独立访问口令门；API 状态点由页壳探测脚本维护。
- `label/readme.md` 是早期设计资料，当前实现和维护以本 README 与 CONTRIBUTING 为准。

### 当前设计器与打印行为

- 页签显示完整“标签设计”“模板管理”文本；默认进入标签创建模式，不自动载入首个模板。
- 基本模板为 100×50mm 底版；公司代码和名称初始为空，保存时均必填，公司代码必须能在客户库匹配名称。
- 公司代码/名称支持从客户库搜索回填；模板和清单使用完整列表，不恢复已移除的分页。
- 文本元素支持 `promptAtPrint`；DN 生成弹窗展示物料明细、份数和大预览，可在打印时输入字段并重复打印。
- 当前 DN 物料仍使用 mock 数据，SAP 自动取数和回写未完成；不得把生成弹窗描述为真实 SAP 数据已接通。
- 设计区与打印预览按当前 **3:2** 弹性比例分配，预览支持滚轮缩放；底部状态条已移除。
- 修改标签资源时，同时检查 iframe src、标签首页和资源版本；必须实际验证设计器，而非只检查 HTTP 200。
