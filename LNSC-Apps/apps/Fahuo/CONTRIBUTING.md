# Fahuo 修改与维护规范

> 修改本应用前先读本文件。目标不是限制功能，而是确保改动落在现有架构内、同步更新当前文档，并能验证和回滚。

## 1. 当前架构基线

以下是不得无意破坏的架构约束：

1. **前端**：原生 HTML + CSS + JavaScript，无框架、无构建步骤；页面结构放在 `pages/N-name.html`，独立交互脚本放在 `assets/js/pages/N-name.js`（纯静态页可无独立 JS）。
2. **前端资源**：共享 CSS、JS、图片、字体和第三方浏览器库分别放入 `assets/css/`、`assets/js/`、`assets/images/`、`assets/fonts/`、`assets/vendor/`，不得在各页复制出不同实现。
3. **生产后端**：`server.py`，仅 Python 标准库，端口 8091；REST API、SQLite、静态文件、路由刷新和承运商分发都在这里。
4. **本地后端**：`server.js` 只用于本地开发，通过子进程调用同一个 `carriers/` 包；不得另写一套生产业务逻辑。
5. **承运商**：`carriers/` 内一家一文件，由 `__init__.py` 注册分发，`base.py` 放公共 HTTP/签名/PDF 能力，`cli.py` 供本地 Node 调用。
6. **标签平台**：已并入 `label/` 和 `server.py` 的 `/api/label/*`；入口是 `pages/6-label.html` 的 iframe。原独立 Node :8092、`label.service` 和独立 webroot 已退役，不得恢复平行服务。
7. **数据**：订单使用 `fahuo.db`；标签生产库使用 `/opt/label/data/label.db`。上传、照片、序列和密钥都是运行时资料，不随代码覆盖。
8. **部署**：只同步运行必需文件；测试、探针、数据库、上传、密钥、本地 Label 工具和字节码不得进入 webroot。

`label/readme.md` 保留的是早期产品设计及目标技术设想，**不是当前实现架构**。新功能必须遵循本文件，不得据此引入 Vue、FastAPI、PostgreSQL 或第二个标签服务。

## 2. 模块边界与改动落点

| 改动类型 | 主要代码落点 | 必须同步检查 |
|---|---|---|
| 录单、地址识别、地址池、异常单 | `pages/1-entry.html`、`assets/js/pages/1-entry.js`，必要时 `server.py` | 共享样式、订单字段、清单显示与搜索 |
| 下单、取消、面单、运单选择 | `pages/2-order.html`、`assets/js/pages/2-order.js`、`carriers/`、`server.py` | 编号规则、回单规则、打印与状态联动 |
| 清单、筛选、导出、附件预览 | `pages/3-list.html`、`assets/js/pages/3-list.js` | 10 列结构、跨列铁律、导出口径 |
| SAP 视图/对接 | `pages/4-sap.html`、`assets/js/pages/4-sap.js` | DN 关联键、API 与部署说明 |
| 标签设计/模板/打印 | `label/`、`pages/6-label.html`、`server.py` | `/api/label/*`、标签库备份、iframe 页壳 |
| 跨页导航/顶栏/统计/主题 | `assets/css/`、`assets/js/` 及全部页面 | 五页一致性、API 状态点、缓存行为 |
| 承运商协议 | 对应 `carriers/*.py` | 注册表、CLI、环境变量、取消/路由/面单、离线测试 |
| 数据字段/状态 | `server.py` 及相关页面 | 自动迁移、JSON 返回、搜索/导出、备份与部署 |
| 部署/安全 | 安装、加固、挂载和备份脚本 | 排除清单、运行时资料、重启与烟测 |

**禁止**把承运商协议写进页面 JS，把页面业务状态塞进承运商包，或为了局部功能新建与现有服务平行的 API 服务。

## 3. 新功能的标准流程

### 新增页面

1. 使用 `pages/N-name.html` 和 `assets/js/pages/N-name.js`，新 HTML 采用 LF、无 BOM。
2. 复用现有页壳、左侧导航、`assets/css/style.css`、`assets/js/topbar.js` 和 `assets/js/stats.js`。
3. 更新所有页面的导航与当前项，不恢复已移除的追溯页或右上标签入口。
4. 更新 README 的当前状态、文件结构和对应页面章节。
5. 验证五页导航、API 状态点、1080P 一屏布局及 API 离线提示。

### 新增或修改承运商

1. 在 `carriers/` 实现协议，公共能力放 `base.py`，并在 `__init__.py` 注册。
2. 同时检查 `cli.py`，确保本地 `server.js` 与生产调用同一实现。
3. 密钥只写环境变量名和用途，不写真值；未配置生产凭证时明确报错，不生成假的正式运单。
4. 客户单号只能由 `next_oid()` 的持久序列分配；DN 永不下发承运商。
5. 覆盖下单、取消、路由、面单和异常响应；优先做不触网的报文断言，真单验证必须明确记录范围。
6. 更新 README 的当前接口规则和 CHANGELOG；事故根因另记 `docs/carrier-incidents.md`。

### 新增或修改 API / 数据字段

1. 先明确请求、响应、错误、默认值和兼容策略，再改 `server.py`。
2. 数据库新增列必须保持启动自动迁移和旧库可用，不清库、不重置序列。
3. 检查所有读取方：录单、下单、清单、SAP、统计、搜索和导出。
4. 更新 README API 表和相关功能说明；不能只把新接口写进变更日志。
5. 验证 Python 语法、接口烟测及静态前端；Python 改动部署后重启 `fahuo-api`。

### 修改标签平台

1. 保持 `pages/6-label.html` iframe 隔离和 `/api/label/*` 单服务架构。
2. 标签模板、客户、规则和历史仍使用现有 SQLite 数据结构及备份机制。
3. 不修改生产库路径来“图方便”，不将 `label/data/`、`label/server.js` 或导入工具部署到 webroot。
4. 同时验证iframe 外层、标签首页和设计器资源；外层强制刷新不等于 iframe 资源已刷新。
5. 当前 SAP 物料仍有的 mock 路径必须明确标记，不得描述成已完成 SAP 对接。

### 修改 UI / 版式

1. 直接更新 README 中的最终规则，不保留每次像素调整和撤回过程。
2. 表格每行展开后的单元格数必须等于 `colgroup` 列数；视觉跨列用 overflow，禁止 `colspan`。
3. 共用 class 改动前检查录单、下单、清单三页，避免只修一个视图破坏另一个。
4. 验证长 DN、长姓名、长备注、空值、外协/其他类型、黑白/蓝色主题和打印。
5. 缓存版本号只是实施细节，不能代替功能验证，也不单独构成一条需求。

## 4. 文档与冲突处理

### 内容归属

- 当前功能、接口和约束：更新 `0_README.md` 对应章节。
- 修改方法和新功能流程：更新本文件。
- 日期化变化：在 `CHANGELOG.md` 顶部历史区之前新增简短条目。
- 事故证据和根因：写入 `docs/carrier-incidents.md`，同时把永久防线写回 README。
- 已完成 TODO：从 README 删除，在 CHANGELOG 留一条结果即可。

### 写作规则

1. 当前文档采用“规则 → 原因/影响 → 必要示例”的顺序，避免按日期反复翻案。
2. 修改规则时替换旧段落，不保留“此前错误、现在终定”的长链；背景确有价值时移到事故档案。
3. 文档和代码冲突时不得猜测：检查当前实现、运行行为和最近变更，明确后同步修正。
4. 历史文件只能追溯，不能拿来覆盖当前文件。`docs/archive/` 不新增内容。
5. 不记录真实密钥、个人电话、客户地址或历史运单；必要示例使用占位符。
6. 缓存版本号、命令输出和烟测清单写入当次变更记录，不堆进当前功能说明。

### CHANGELOG 条目模板

```text
## YYYY-MM-DD 模块：变化摘要
- 变化：当前行为如何改变。
- 文件：主要代码与文档。
- 验证：实际执行的检查及结果。
- 迁移/回滚：仅在有数据库、配置或部署注意事项时填写。
```

## 5. 部署和运行时资料边界

- 只同步 README 文件结构中明确的运行文件及新增加的必需文件。
- 不同步测试/探针、数据库、`.db-wal/.db-shm`、`oid.seq`、`carriers.env`、`Upload/`、`ShippingPhotos/`、`shipphotos.json`、`label/data/` 和 `__pycache__/`。
- 静态 HTML/CSS/JS 改动通常只需刷新浏览器；`server.py` 改动必须重启 `fahuo-api`，配置改动按安装脚本要求重启。
- 不在生产执行离线探针，不为验证方便打印完整凭证、真实客户资料或历史运单。
- 不清空 webroot，不递归删除应用目录；`ShippingPhotos/` 可能仍是挂载点。
- 部署后至少验证 `/api/stats`、目标页面、关键静态资源和本次修改的 API；静态资源 200 不等于业务功能已验证。

## 6. 完成定义（Definition of Done）

提交前逐项确认：

- [ ] 改动落在既有模块，没有引入未批准的框架、构建步骤或平行服务。
- [ ] 当前 README 已更新，旧矛盾已删除，而不是继续追加补丁。
- [ ] CHANGELOG 有简短记录；事故或运维风险已放到对应文档。
- [ ] 数据字段、搜索、导出、状态和关联页面已做影响检查。
- [ ] 未泄露密钥、运行时数据库、上传文件、真实运单或个人资料。
- [ ] 新增探针/临时脚本默认不入生产；一次性脚本完成后按约定清理。
- [ ] 已运行可行的语法检查、离线测试或页面/接口烟测，并如实记录未验证项。
- [ ] `git diff` 只包含本任务文件，没有覆盖他人的未提交改动。

## 7. 明确禁止的回退

- 把 DN 或数据库自增 ID 作为承运商客户单号，或重置 `oid.seq`。
- 把顺丰 `expressTypeId` 的 1/2 映射写反。
- 用 `isSignBack=2/3` 代替 IN91 拍照回传，或给纸质回单额外套 IN03。
- 把 SF106 回单号塞回 `masterWaybillNo`，或以本地厂内面单冒充顺丰反向回签单。
- 顺丰路由省略 `checkPhoneNo`，或将空路由统一显示成“待揽收”。
- 让清单回单日期重新取主单 `signed_at`，或让新单仅凭回单运单终态自动置实物回单。
- 用 `colspan` 解决视觉跨列，破坏表格列数一致性。
- 恢复独立标签服务、已删除的追溯页或右上标签图标入口。
