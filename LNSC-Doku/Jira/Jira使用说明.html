Jira 使用说明

面向团队的敏捷项目管理工具：看板视图、Sprint 规划、状态流转、自动化与报告。一页看懂核心概念，附 1v1 动画演示，像教练手把手带你走完整条工作流。

功能亮点

Jira 帮助团队把想法变成可交付的成果，覆盖需求、开发、测试到发布的全过程。

📋

看板视图

Backlog → To Do → In Progress → Done，拖拽卡片即可流转状态，工作进度一目了然。

🏃

Sprint 规划

按迭代规划容量与优先级，用 Velocity、Burndown 等图表度量团队节奏。

🔁

工作流流转

自定义状态与流转规则，自动记录操作历史，谁在什么时候做了什么，全程可追溯。

🤖

自动化规则

"当 Issue 分配给我时自动打标签""测试通过自动流转 Done"——重复操作交给 Jira 完成。

📊

报告与度量

燃尽图、燃起图、累积流量图，用数据回答"进度如何、瓶颈在哪、下个 Sprint 能做多少"。

🔌

集成与扩展

对接 Git / CI-CD / Confluence / Slack，代码提交、测试结果、文档链接自动关联到 Issue。

快速上手 · 四步开始

从零到跑通第一条完整工作流，只需要四步。

1

创建项目

新建 Scrum 或 Kanban 项目，邀请团队成员加入。

2

创建 Issue

录入用户故事、任务、Bug，补充描述、标签与优先级。

3

规划 Sprint

从 Backlog 挑选任务进入迭代，估算 Story Points。

4

开发 & 发布

拖拽卡片流转状态，测试通过后进入 Done，冲刺完成！

❓ 常见问题

新手最常遇到的 6 个问题，都在这里。

Scrum 适合按固定迭代（Sprint）推进、有明确版本节奏的团队；Kanban 适合需求持续流入、追求持续交付的运维 / 支持团队。拿不准可以先用 Scrum。

Issue 是 Jira 中一切工作的统称；Task / Sub-task 是把它拆解后的子项。一个用户故事（Story）下可以拆多个子任务，子任务完成后故事才算 Done。

Story Points 衡量的是工作量与复杂度，不是时间。常用斐波那契序列（1、2、3、5、8、13）。新团队可以先用"类似已交付任务"做类比估算。

技术上可以，但 Scrum 最佳实践是先移除等量任务、经团队同意后再加入，保持 Sprint 目标稳定，避免进度被打乱。

在 Commit Message 或 PR 标题中带上 Issue Key（如 FUNC-12），Jira 与 Git 集成后会自动把代码提交关联到 Issue 的"Development"面板。

检查是否 WIP（在制品）过多。设置合理的 WIP 上限，让团队一次少做几件事；也可以用累积流量图找出流程瓶颈。
